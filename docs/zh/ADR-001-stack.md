# ADR-001：技术选型（2026-10）

**语言：**[English](../ADR-001-stack.md) | 简体中文

## 已采纳

| 领域 | 选型 | 原因 |
|---|---|---|
| 架构 | 模块化单体 + 可替换的端口/适配器 | 便于本地部署和调试，同时保留后续拆分边界 |
| 运行时 | Python 3.12 / FastAPI / Pydantic v2 | API 类型清晰，也符合现有学习路径 |
| 依赖管理 | Docker / pip / `pyproject.toml` | 统一容器运行、开发和 CI 测试环境；依赖锁定计划后续完善 |
| 事务数据 | MySQL 8.4 / SQLAlchemy 2 异步接口（`asyncmy`）/ Alembic | 用于认证、数据归属、会话状态、任务事件和幂等处理的事务型存储 |
| 临时数据与事件 | Redis | 用于缓存、限流和短时事件流；不能作为唯一的持久化状态来源 |
| RAG 向量库 | 隔离部署的 Milvus 2.6.24 + etcd + 专用 MinIO | Compose 部署可复现，内嵌 Woodpecker，现有 Milvus 数据保持独立 |
| 文档和附件 | 独立的文档 MinIO | 凭据、数据卷和 Bucket 相互隔离；文件处理流程后续实现 |
| Agent | 显式对话/任务状态机 + 受控工具循环（第二阶段） | 业务状态转换可预测，内部实现清晰易读 |
| 模型 | 通过自有 ModelGateway 调用 OpenAI 兼容 API | 先接入一个模型，同时支持供应商配置、追踪、Token 和超时预算 |
| 界面 | React + Vite + TypeScript + Tailwind/shadcn（第二阶段） | 构建轻量的客户与客服交互界面 |
| 可观测性 | OpenTelemetry + Langfuse（第二阶段） | 保持供应商中立的追踪，记录完整的 LLM/工具决策过程 |
| 测试 | pytest + 多轮对话基准样例 + 离线评测 | 验证动作、槽位、任务完成和请求重放；LLM 评审仅作补充 |
| Worker | Celery + Redis，可选（第三阶段） | 异步处理文档索引和评测，不在请求路径内执行副作用 |

## 未列为第一版必需基础设施

- **LangGraph：**检查点和人工介入能力完善。等确实需要执行图、图检查点或可恢复中断时再引入。未来可将 `conversation_id` 映射为 `thread_id`，但业务事实仍以 MySQL 为准。
- **Temporal/DBOS：**适用于持久化的长时间运行流程，与保存聊天记录是不同问题。出现数小时工作流或定时补偿需求后再评估。
- **Kafka、Kubernetes 和多个 Agent 微服务：**当前吞吐量和规模不足以支撑其额外运维成本。
- **ChromaDB：**新 RAG 功能不再采用，但可以单独增加导出/导入迁移工具；不要删除现有 EchoMind 集合。

## 必须保持的约束

1. 所有会话读取和写入都必须校验 `tenant_id + user_id`，不能只依赖 `conversation_id`。
2. 每个客户端轮次使用稳定的请求 ID，并且只记录一个处理结果。
3. 对话历史不是任务状态的权威来源。任务状态必须保存业务参数、阶段、审批和待补充槽位。
4. LLM 输出属于不可信输入；执行动作前必须完成结构校验和业务授权。
5. 切换 Agent 不等于创建新的客户会话。
6. 模型、Milvus、Redis 或后台 Worker 故障时，应能降级运行，且不能丢失权威业务记录。
