# 开发路线图

**语言：**[English](../ROADMAP.md) | 简体中文

## 阶段一：意图识别（已完成首版）

- 固定消息、动作、实体、关系和歧义的结构化契约。
- 识别话题切换、补充回答、更正、多动作及信息不足的请求。
- 返回结果前校验模型结构和原文证据。
- 冻结数据集，记录原始请求、响应、源码快照和指标。
- 收集人工复核及脱敏真实口语样例，再讨论准确率结论。

## 阶段二：对话策略与状态归约器（首版已完成，持续扩充评测）

- 决定语义动作应新建、补充、恢复、更正还是取消任务。
- 意图、任务目标或必需参数仍不明确时，提出针对性的澄清问题。
- 无关话题打断时保留原始待办请求，后续仍可恢复。
- 实现纯状态归约器：只根据输入事件返回新状态与领域事件，不执行 I/O。
- 评测任务切换、否定表达、互斥选项和多动作的安全边界。

阶段二首版已接入聊天 API：纯内存领域状态、确定性策略与状态归约器覆盖创建、补充、恢复、更正、取消、政策问答、条件延后和待澄清上下文。固定语义输入策略集通过 14/14 轮，真实聊天 API 端到端集通过 25/25 轮、10/10 场景。数据集仍是未经独立人工复核的合成回归集，后续需持续扩充和人工复核。会话目前保存在服务进程内存中，MySQL 持久化尚未实现。

## 阶段三：持久化与生产 API 工作流

- 当前聊天 API 已串联意图识别、策略和归约；下一步在状态规则明确后加入 MySQL 会话、任务、消息和事件记录。
- 模型请求放在数据库事务之外；写入边界加入版本检查和幂等控制。
- 部署前落实身份认证、租户授权、数据保留和审计规则。

## 阶段四：工具和 Agent Runtime

- 加入有类型且按权限限制的业务工具，并制定超时与幂等策略。
- 重要操作要求确认，并记录每次执行结果。
- 仅在真实场景需要时加入不确定结果恢复和后台任务。

## 阶段五：RAG、记忆与生产评测

- 支持流程确实需要时再加入文档解析与检索。
- 将权威任务状态与可检索记忆、向量索引分开管理。
- 扩充人工复核的留出集、回归门槛、延迟和成本指标。
