# 意图分类体系 v1 接入与复测

**语言：**[English](taxonomy-migration.md) | 简体中文

## 本次交付

模型契约、提示词、策略、API 响应和聊天界面已使用 `refund.apply`、`logistics.track`、`policy.consult`，解释结果包含 `taxonomy_version: "1.0"`。旧语义名称可兼容输入，响应统一为正式 ID。

任务状态类型仍为 `refund`、`logistics`。注册目录提供意图到任务类型的映射及必填参数，避免将正式意图名称误当作旧任务类型。历史咨询焦点也有显式恢复映射。未增加可执行的新业务、真实工具或多 Agent 路由。

五份新数据由[迁移脚本](../scripts/migrate_intent_taxonomy.py)生成，[迁移清单](../datasets/taxonomy_v1_migration.json)记录源文件和目标文件 SHA-256。用户原文、订单参数、任务类型和评分规则不变；历史数据和全部失败记录保留。

## 未通过项保留

用户消息：“帮我订一张明天去上海的火车票”。

既有聊天标签要求报告 `intent` 歧义、发起澄清，并进入待澄清状态。当前明确范围外规则返回空业务动作、空歧义和能力范围提示，不创建业务任务，因此严格评分仍失败。该轮任务状态断言通过，但澄清动作、类型和回复短语断言不通过。

这是一项范围外处理约定与旧标注的差异，需要明确评审后在新的数据版本中统一。本轮没有改动旧标签，也没有将它记为通过。当前契约尚未单独区分寒暄与范围外请求，回复仍可进一步改进。

初期回归暴露了任务歧义时丢失已知动作、泛化否定提及及将纯订单查询猜成物流等问题。提示词补充通用边界，任务候选由策略按当前 State 核实；没有使用消息字符串特判来返回固定结果。

多轮策略还修复了两个具体问题：新业务缺参数时可暂存旧澄清；新退款提供的订单号不得用来回答旧物流澄清。专门的回归测试验证了跨业务参数保护、同业务补参正常恢复，以及全局歧义不触发新任务。

并行查询的诊断发现，模型会把共享谓词拆成重新拼接的句子，导致 utterance_span 不是原文连续子串。现在明确允许多个动作引用同一完整原句，并把固定的原文、实体或任务引用校验类别反馈给唯一一次纠正调用。没有放宽原文校验、复制实体、增加重试次数或向用户返回供应商原始错误。

## 结果边界

这些是合成开发回归集，部分规则根据上述失败调整，不是独立盲测。模型输出仍会波动；分数衡量包含一次结构纠正的完整解释器，不代表首次调用准确率或生产准确率。独立诊断调用不计入正式评测分母，也不替换已失败的样例。

本次不验证 MySQL、真实退款/物流、认证权限或多 Agent 调度。参数缺失和歧义在状态表示上仍需持续规范；目录中的未来业务和能力声明不能当作已经实现的业务。
